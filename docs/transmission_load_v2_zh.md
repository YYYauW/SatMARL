# 光学遥感卫星观测与数据交付测试 v2

此文档保留v2条件。当前入口默认采用全天事件计时v3，见 `docs/transmission_day_v3_zh.md`。复现本文全部v2命令时，应显式添加 `--config configs/transmission_load_v2.json`。

本版入口为 `scripts/run_transmission_load.py`，协议为 `optical-ground-delivery-v2`。
旧的 `configs/thousand_paper_suite.json`、训练权重和历史结果保持不变。
新入口使用 `TransmissionEnv`；直接运行旧的 `evaluate_marl.py` 仍使用原环境。

## 1. 本次调整和结果使用范围

本次实现以下过程：

1. 点目标请求携带一次成像产生的原始数据量；压缩后的存储需求为原始量的四分之一。
2. 每次独立成像产生完整的数据包。需要多个卫星观测的请求，每个贡献卫星分别生成数据。
3. 用轨道位置和地面站位置计算天线仰角，求出仰角范围内的接触区间。
4. 卫星发起下传后，接收天线在接触区间内持续接收队列中的数据，直到队列清空或该接触区间结束。
5. 天线资源允许一个窗口依次传输多个目标的数据；未传完的数据包可在后续窗口继续传输。
6. 每颗卫星在任意滚动90分钟内，成像累计时间最多30分钟。
7. 分别统计观测成功的请求数，以及观测成功且所需数据完整到达地面的请求数。

已有模型可通过新入口做迁移测试，权重保持不变。新实验改变了存储、数据量、地面站、传输过程和载荷配置，属于新环境下的评估。历史论文数值继续对应原实验条件。新环境下的正式方法比较需要统一训练/评估协议后重新运行；本脚本只提供评估，不执行训练。

| 任务优先级 | 1–10 | 沿用目录生成器 |
| 请求时间窗 | 8–32步，即4–16 min | 指观测有效期；交付统计截至120分钟场景结束 |
| 能量模型 | 最大100；初始70%–100%；日照每步补充1.8 | 归一化模型，尚未标定为Wh；原成像/机动耗能公式保留 |

目标是地理点，数据来自该点对应的一次影像获取。目录中的两个字段是：

- `original_data_mb`：一次成像的原始数据量。
- `memory_required_mb`：一次成像的压缩后存储需求，必须等于前者除以4。

例如，一个请求需要3颗卫星分别观测，每次原始数据为4000 MB，则每颗卫星产生1000 MB压缩数据，完整请求共需交付3000 MB。

2000–8000 MB是图像数据量的工程场景假设。计算示例：20 km × 20 km影像、0.5 m采样间距、单波段10 bit量化，对应约2000 MB原始数据。具体任务的数据量还取决于影像范围、波段数、采样和量化；当前由目标目录显式给出，不从点坐标直接推定。

每个测试使用同一组目标需求阈值：分辨率≤2 m、幅宽≥10 km。实际成像几何仍需满足离轴、分辨率、幅宽和太阳高度角等检查。姿态与能量沿用原调度模型，观测成功在已接纳成像的实际结束时刻之后计数。

5秒成像、30秒决策步和30秒冷却使当前单星成像占空比较低，30分钟预算可能不触发。结果导出 `max_rolling_imaging_seconds`，可核查这一约束的实际活跃程度。不能据此声称成像30分钟上限构成了实验瓶颈。

## 3. 地面站与传输参数

| 参数 | v2测试设置 | 说明 |
|---|---:|---|
| 数据下传链路参考 | X频段 | 本模型不执行RF链路预算 |
| 单星单链路标称码速率 | 900 Mbps | 参考国内常见X频段单通道速率和武汉一号公开参数 |
| 有效数据效率 | 0.8 | 仿真折算系数，非行业统一值 |
| 有效净吞吐 | 720 Mbps = 90 MB/s | MB为十进制，不是MiB |
| 仰角范围 | 10°–90° | 可配置的仿真天线掩膜；真实站点可替换其上下限 |
| 窗口扫描 / 边界细化 | 1 s / 0.01 s | 扫描后对仰角越界做二分求根；短于1秒且完全落于采样间隙的擦边接触可能遗漏 |
| 地面站数 | 5 | 密云、喀什、三亚、丽江、漠河的地理代理站点 |
| 各站同时接收卫星数 | 2 | 每站2个独立跟踪接收资源，研究配置假设 |
| 单星同时占用接收资源 | 1 | 不把卫星的双极化/双RF通道当作两颗卫星 |
| 数据包调度 | 成像结束时间FIFO，优先级打破平局 | 包可分段；一个接触内顺序发送多个包 |
| 持续下传 | 发起一次后持续至队列清空或接触区间结束 | 下一窗口由策略再次发起；卫星下传时不接受新的成像动作 |
| 天线冲突处理 | 已有会话优先；新请求按队列紧迫度排序 | 可用同站剩余时段或其他可见站；清空后释放接收资源 |
| 下传期限 | 场景结束 | 当前请求deadline为观测deadline，无额外数据交付deadline |
| 天线切换/捕获额外时间 | 0 s | 本版按接触几何和接收资源调度，未单列捕获与重定向时间 |
| 通信耗电 | 未单独标定 | 归一化能量模型沿用原实现；30分钟只计载荷成像时间 |

站点坐标为调度仿真的公开地理代理，名称保留 `_proxy`，避免将城市近似点标作天线精密坐标。后续有实测站址可在 `TransmissionConfig.ground_station_sites` 或配置的同名字段中替换。

| 地理代理 | 纬度 / 经度（度） |
|---|---|
| Miyun_proxy | 40.45 / 116.85 |
| Kashgar_proxy | 39.47 / 75.99 |
| Sanya_proxy | 18.31 / 109.31 |
| Lijiang_proxy | 26.88 / 100.23 |
| Mohe_proxy | 52.97 / 122.53 |

星地仰角由卫星ECEF位置、站点ECEF位置和地面局部天顶方向计算。接触区间是仰角同时满足上下限的时段。区间按物理步分段积分，会话可跨物理步持续。

对某次实际获分配的传输时段 `[a,b]`：

`可发送数据量(MB) = 900 × 0.8 × (b-a) / 8`。

例如，10秒可发送900 MB，30秒可发送2700 MB。实际发送量还受已生成数据量、有效接触时段和天线分配限制。旧的 `32 MB/step × sin(elevation)` 不参与新版传输计算；导出的兼容字段 `ground_station_rate_mb_per_step` 被更新为2700 MB/30 s。

轨道缓存区间内采用ECEF位置与速度的三次Hermite插值计算接触边界；直接六根数轨道使用连续时间开普勒传播。扫描分辨率、插值轨道与物理步离散化均作为实验条件记录。

## 4. 两种成功指标

`observation_success_tasks`：某个请求要求的有效卫星观测贡献已经接纳，且这些成像均已到达结束时刻。多次观测请求整体只计1个请求。

`observation_and_downlink_success_tasks`：上述请求所需观测均已结束，而且关闭该请求所用贡献的全部压缩数据已到达地面。只传了部分数据或只交付了部分卫星的贡献时，不计交付成功。

同时导出两种成功率、观测成功但未完整交付数量、观测优先级总和、完整交付优先级总和、已下传MB、待下传MB、接收资源占用秒数和滚动成像时长。

`admitted_completed_tasks`保留接纳时的原计数以供核对。新版通用别名 `completed_tasks` 对应已结束的观测成功数。单个数据包只有到成像结束后才允许开始发送。存储在接纳时预留，发送后按字节释放。

结果保留每次成像的起止秒数、原始/压缩数据量和完整交付时刻；第一评估回合还保留每个请求的两个成功标记。可加 `--save-all-ledgers` 输出全部回合明细。

## 5. 固定卫星规模、改变目标数量

原来的 `M=48N` 用于考察保持星均需求负载时的星座扩展性。它同时改变卫星数和需求总量，不能单独辨识需求负载的影响。

新主实验采用交叉矩阵：

| 固定卫星数 N | 在此星数下分别测试的目标请求数 M |
|---:|---|
| 128 | 6144、12288、24576、49152 |
| 256 | 6144、12288、24576、49152 |
| 512 | 6144、12288、24576、49152 |
| 1024 | 6144、12288、24576、49152 |

在每个N下，轨道、载荷、站点、速率、存储、时间范围和成像预算固定。每回合生成最大M的主目录，较小M读取同一目录前M个请求；方法与星数共享该回合的目录。目录已随机打乱，所以较小M保留嵌套关系，属性比例允许有抽样波动。

不同回合使用不同目录种子。各方法/训练种子共享同一批目录与初始条件，实现配对评估。默认每个模型20回合；先在每个训练种子内统计，再合并701、702两个模型的均值。`grouped_across_training_seeds.csv`单列训练种子间标准差，避免将同一权重的20次评估视作20个独立训练。

主要结果图可固定N=512或1024、横轴M，分别画观测成功数、完整交付数、优先级、运行时间与待交付量。补充图固定M、横轴N。原来的比例扩展曲线可以保留为扩展性补充结果。

## 6. 服务器命令

在项目根目录操作，不需要重新启动原训练调度器。

先进行小规模规则策略冒烟检查（不加载神经网络）：

```bash
cd ~/SatMARL
conda activate satmarl
python scripts/run_transmission_load.py \
  --run-root runs/transmission_v2_smoke \
  --policy priority --smoke
```

检查指定模型的测试计划（只打印，不创建目录或运行实验）：

```bash
python scripts/run_transmission_load.py \
  --run-root runs/transmission_v2_n512 \
  --model-root runs/thousand_paper_suite/training \
  --methods full,mappo,no_reservation --training-seeds 701,702 \
  --satellites 512 --task-counts 6144,12288,24576,49152 \
  --episodes 20 --plan-only
```

确认后，去掉 `--plan-only`执行，建议先用`--methods full --training-seeds 701 --episodes 1`检查真实模型兼容性；完整运行使用新的独立目录：

```bash
python -u scripts/run_transmission_load.py \
  --run-root runs/transmission_v2_n512 \
  --model-root runs/thousand_paper_suite/training \
  --methods full,mappo,no_reservation --training-seeds 701,702 \
  --satellites 512 --task-counts 6144,12288,24576,49152 \
  --episodes 20 --device cuda
```

模型路径约定：`训练目录/方法/seed_701/checkpoints/latest.pt`。方法列表可填写已有其他模型目录，如 `oasis_graph,ippo,qmix,ps_dqn`。网络特征宽度从其训练元数据读取；模型选择权重不改变。

同一实验被中断后，使用完全相同的命令附加`--resume`。协议、代码、参数、模型和目录哈希必须一致；已完成的条件会跳过，未完成条件从该条件的第1回合重新运行。确认旧进程已经结束后，才能处理因非正常断电留下的`runner.lock`。

`--prepare-only`只准备轨道/目录；`--rate-mbps 450`或`1200`可在新run-root做速率敏感性比较；`--imaging-minutes 30`显式指定用户选定的成像预算。

## 7. 输出

- `manifest.json`：协议、参数、代码和模型哈希。
- `scenario/`与`scenario_sha256.json`：轨道缓存和每回合目标目录。
- `jobs/*.json`：每个方法/训练种子/N/M的评估结果，以及第一回合的任务和成像数据明细。
- `episodes.csv`：每回合结果。
- `grouped.csv`：每个训练种子内部的回合统计。
- `grouped_across_training_seeds.csv`：先按训练种子汇总后合并的结果。
- `progress.json`：完成状态。
- `ledgers/`：加`--save-all-ledgers`后保存的全部回合详细记录。

脚本检查 `已接纳压缩数据 = 待传数据 + 已传数据` 的数据守恒，以及每颗卫星的滚动成像预算。所有方法使用完整120分钟场景，观测结束后仍可继续下传。

`episode_wall_seconds`统计环境构建、初始化与rollout的总耗时，不含结果序列化；第一回合还含神经网络实例化。若需要单独比较策略推理开销，应另设推理时间指标。
